# PHYSIO MARKET
منصة داخلية لذكاء سوق أجهزة ومستلزمات العلاج الطبيعي والتأهيل، مع فصل كامل عن أي مشروع آخر.

## تشغيل النسخة الحالية
نزّل ZIP من GitHub، فك الضغط، وافتح \`index.html\` في Edge أو Chrome.

## إدارة السجلات
- إضافة وتعديل وحذف الأجهزة والمستهلكات والشركات والمصانع والعلامات والموزعين وعروض الأسعار ورصد الأسعار والشحن والمراجع والمصادر.
- إنشاء أكواد تلقائية فريدة؛ الأكواد المحذوفة تظل محجوزة في سجل محلي ولا يعاد استخدامها.
- ربط الجهاز بالعلامة التجارية والمصنع/المورد والموزع، وإنشاء رصد سعر مرتبط بالمنتج والشركة والمصدر.
- ربط عروض الأسعار بالمورد والمنتج والمصدر.
- البحث الشامل وتصدير CSV لكل قسم.
- يحفظ النموذج الحالي التغييرات في Local Storage بالمتصفح والجهاز الحالي. لا توجد مزامنة بين الأجهزة ولا صلاحيات مستخدمين ولا نسخ احتياطي تلقائي.

## الأكواد
DEV الأجهزة، CON المستهلكات، SPR قطع الغيار، EGC الشركات المصرية، CNF المصانع/الموردون الصينيون، BRD العلامات، DST الموزعون، QTN عروض الأسعار، PRC رصد الأسعار، SHP الشحن، REG المراجع التنظيمية، DOC المستندات، CUS العملاء، SRC المصادر. الأكواد ثابتة وفريدة ولا يعاد استخدامها.

## حالات البيانات
- verified: تحقق مباشر حديث.
- needs_review: يحتاج مراجعة أو تواصل.
- platform_reference: سعر استرشادي منشور على منصة.
- reference: مرجع معلوماتي/تنظيمي.

لا تعتبر سعر المنصة عرضًا مؤكدًا ولا تعتبر ذكر العلامة إثباتًا لاعتماد الموزع.

## البنية التقنية
الواجهة الحالية تطبيق Static HTML/CSS/JavaScript. ملف \`database/schema.sql\` مخطط PostgreSQL مقترح فقط، وغير متصل حاليًا. لا تضع كلمات مرور أو مفاتيح API أو بيانات تفاوض سرية في ملفات الواجهة. الخطوة التالية قبل تعدد المستخدمين: Backend/API، قاعدة PostgreSQL مستضافة، مصادقة وصلاحيات، سجل تدقيق، نسخ احتياطي، ومزامنة آمنة.

- هذا البيان يوثق النسبة التعريفية المتفق عليها داخل ملفات المشروع، ولا يُعد بمفرده تسجيلًا قانونيًا أو اتفاقًا تفصيليًا للحصص والحقوق.

## البحث والتنقل — تحديث واجهة البيانات
- البحث الشامل يدعم تطبيع عدد من اختلافات الكتابة العربية (مثل أ/إ/آ، التشكيل، والتطويل) مع البحث في الحقول النصية والأكواد.
- صفحات الأقسام تعرض زر «عرض» لفتح ملف تفصيلي للسجل.
- ملف السجل يعرض حقوله المسجلة، وروابطه وسجلات الأسعار وعروض الأسعار المرتبطة متى كانت موجودة.
- البحث داخل القسم يستخدم آلية التطبيع نفسها.
- ما زال البحث محليًا داخل البيانات المحملة في المتصفح، وليس بحثًا على الإنترنت أو قاعدة بيانات مشتركة.

## قاعدة البيانات المركزية — تجهيز الربط
- أُضيف مخطط أولي لجدول مساحة العمل المشتركة في `supabase/workspace.sql` باستخدام JSONB للحفاظ على نموذج البيانات الحالي أثناء الانتقال.
- انسخ `supabase-config.example.js` إلى `supabase-config.js` واملأ رابط مشروع Supabase ومفتاح Publishable/anon فقط.
- شغّل SQL في Supabase SQL Editor.
- المزامنة لم تُفعّل بعد؛ يلزم تنفيذ وربط المصادقة وعميل المزامنة في الواجهة، ثم اختبار صلاحيات المستخدمين والنسخ الاحتياطي. لا تضع service_role أو أي مفتاح سري في GitHub Pages.

## طبقة الذكاء التجاري — إضافة أولية
- أُضيفت أقسام العملاء والجهات المستهدفة، العلاقات التجارية، الفرص والصفقات، والمعلومات الميدانية في `intelligence.js`.
- تتضمن النماذج طبيعة المعلومة (منشورة/ميدانية/تجارية حساسة)، المصدر، تاريخ الرصد، درجة الثقة، السرية، وبيانات المتابعة.
- يسجل سجل التعديلات المحلي الإضافة والتعديل والحذف واسم المستخدم المختار داخل الواجهة.
- صفحة النسخ الاحتياطي تصدر قاعدة العمل بصيغة JSON وتستورد السجلات ذات الأكواد الجديدة فقط، وتتجاوز الأكواد المتعارضة دون استبدال البيانات الحالية.
- الإضافة لا تنشئ مزامنة بين الأجهزة ولا تسجيل دخول. اسم المستخدم المختار للتوثيق الداخلي فقط وليس مصادقة أمنية.
- **تنبيه أمني:** GitHub Pages واجهة عامة وملفات `data.js` متاحة للزوار. لا تضع بيانات عملاء حساسة أو عروض تفاوضية حقيقية في ملفات المشروع المنشورة. بيانات Local Storage تبقى على المتصفح الحالي ولا تُعد مشفرة أو محمية من مستخدمي الجهاز.
